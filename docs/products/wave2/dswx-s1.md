# OPERA DSWx-S1: qualified production slice

This Wave 2 gate targets **product 1.0 generated by SAS 1.2**, not every DSWx-S1 revision. The pinned production granule is `OPERA_L3_DSWx-S1_T17SQV_20261021T230515Z_20261023T070839Z_S1D_30_v1.0`, CMR `G4385346748-POCLOUD`, in collection `OPERA_L3_DSWX-S1_V1` (`C2949811996-POCLOUD`, collection version 1.0). CMR records PGE 3.0.4. The inspected current satellite is Sentinel-1D; older S1A/B-only documentation is insufficient to describe this asset.

The [request](dswx-s1-request.json) retains exact provider ETags. The [source receipt](dswx-s1-source-inspection.json) retains canonical URLs, SHA-256, complete GeoTIFF metadata, raw class counts, geometry, and source RTC lineage. Raw captures remain in ignored `prototype-output/wave2-dswx-s1/`. A CLI success is qualified only when `dswx-s1-native-validation.json` reports `passed` after independent reopening and comparison.

| Asset | Source dtype / fill | Interpretation |
| --- | --- | --- |
| B01_WTR | UInt8 / 255 | 0 not water; 1 open water; 3 inundated vegetation; 250 HAND; 251 layover/shadow; 254 ocean mask when used; 255 fill |
| B02_BWTR | UInt8 / 255 | Binary water class 1, not water 0, with independent mask precedence |
| B03_CONF | UInt8 / 255 | Categorical confidence classes, including wetland-prefixed classes 30/31/32/35/36/37; **not a continuous probability** |
| B04_DIAG | UInt8 / 255 | Fuzzy score 0–100, with mask/fill classes; **not the HLS UInt16 decimal diagnostic layer** |

All four actual TIFFs have one band, 3660 × 3660 pixels, 512 × 512 tiles, DEFLATE compression, EPSG:32617, pixel-is-area, affine `[30,0,699960,0,-30,4000020]`, scale 1 and offset 0. Native integer class values are preserved. The explicit `dswx_s1_wtr_water` mask accepts WTR 1 or 3. The separate `dswx_s1_bwtr_water` mask accepts BWTR 1; each mask belongs to its own source layer. Source validity means non-fill within the AOI; HAND and layover labels remain visible and do not silently become missing data. There are no HLS cloud or shadow policies here.

Two actual-source differences prevent naive reuse of older assumptions. The current CMR collection summary says three TIFFs, while its exact granule links and inspected bytes provide four. Rev A's DIAG table lists fill 120 and masks 252/253; the actual SAS 1.2 file and tagged [SAS class assignments](https://github.com/opera-adt/DSWX-SAR/blob/v1.2/src/dswx_sar/dswx_sar_util.py) use fill 255 and the common mask scheme. Actual DIAG values span 0–100, 251, and 255 in this scene. The source receipt records these differences without rewriting bytes.

WTR and BWTR are not exactly interchangeable: 22 full-scene pixels are WTR 3 and BWTR 251. Tagged [SAS layer construction](https://github.com/opera-adt/DSWX-SAR/blob/v1.2/src/dswx_sar/save_mgrs_tiles.py) applies inundated vegetation as a later WTR override, while BWTR retains layover/shadow precedence. Their independent raw arrays remain authoritative for each band.

The filename's earliest acquisition is 23:05:15, but this tile's CMR and TIFF `RTC_SENSING_START_TIME` are 23:05:34 through 23:05:53. The filename generation stamp is 07:08:39; the TIFF processing time is 07:09:36. The request uses the exact CMR observation time and retains both filenames and TIFF metadata. CMR lists collection-wide RTC inputs, while TIFF `RTC_INPUT_LIST` lists the seven tile-local input bursts. These distinct fields are preserved.

Authentication uses an explicit private URS netrc. The observed production chain is canonical PO.DAAC object → URS `/oauth/authorize` → archive `/login` → the same canonical object → the **same object key** behind the existing PO.DAAC CloudFront resource gate. Basic credentials are sent only to URS; provider signed query strings remain in memory. Every body capture is a conditional Range GET bound to its ETag, with an 8 MiB per-object ceiling. No permanent credential or broad arbitrary-host redirect policy is introduced.

Reproduce from the repository root with the existing rasterio/xarray environment:

```sh
prototype-output/zarr-env/bin/python bench/wave2_dswx_s1.py \
  --capture --netrc /absolute/private/netrc
prototype-output/zarr-env/bin/python bench/wave2_dswx_s1.py \
  --binary target/debug/tile-ripper --netrc /absolute/private/netrc \
  --output prototype-output/wave2-dswx-s1/native.zarr
```

The second command uses the public `fetch` CLI and reopens each Zarr group with xarray. The independent gate compares exact UInt8 values, valid and AOI masks, the explicit WTR water policy, projected coordinates, CRS, source ETags, product version, and canonical source identity against rasterio windows from the original captures. The bounded AOI exercises non-water, open water, inundated vegetation, layover/shadow, and source fill. This is scientific-equivalence evidence, not a broad product accuracy assessment or a speed claim.

Primary specifications and metadata: [JPL product suite](https://www.jpl.nasa.gov/go/opera/products/dswx-product-suite/), [Rev A product specification](https://archive.podaac.earthdata.nasa.gov/podaac-ops-cumulus-docs/web-misc/opera/D-108761_OPERA_DSWx_S1AB_ProductSpec_Rev_A.pdf), [CMR exact granule](https://cmr.earthdata.nasa.gov/search/granules.umm_json?concept_id=G4385346748-POCLOUD), and [tagged SAS 1.2](https://github.com/opera-adt/DSWX-SAR/tree/v1.2).


## Frozen comparison and failure checks

The [frozen receipt](dswx-s1-frozen-validation.json) replays the original captured bytes through the existing version-bound local mirror, with zero upstream requests during replay. Both native and independent rasterio→Zarr workflows use the same approved 272 × 272 window, all four layers, both water policies, the same 64-pixel output chunks, and the same metadata contract. The independent workflow uses four GDAL source-window reads and encodes its own values, masks, axes, timestamp, and CRS scalar. Metadata is copied from the approved manifest; scientific arrays are independently calculated. Every reopened output array compares exactly. AOI membership is computed by independently inverse-projecting each pixel center to the requested geographic bounds; projecting only four geographic corners changes twelve boundary pixels for this AOI.

| One local frozen run | Native | Rasterio → Zarr |
| --- | ---: | ---: |
| Wall time, including process startup | 0.353 s | 0.665 s |
| CPU | 0.433 s | 0.645 s |
| Peak process RSS | 42,795,008 B | 135,921,664 B |
| HTTP GET requests | 22 | 8 |
| HTTP response body bytes | 346,685 B | 409,600 B |
| Output objects | 450 | 470 |
| Output bytes | 2,123,322 B | 2,238,709 B |

This is a single loopback run, not an archive-speed result. Native performs more HTTP requests in this example. The native physical plan selects 295,936 bytes, visits eight unique source blocks, and has a source-block decoded-to-selected-byte ratio of 7.087. It plans 120 block visits, including 112 repeats; measured HTTP ranges contain no duplicate bytes. The reader's reservations and process RSS have different scopes.

The same frozen source passes `stream --values` over 100 provisional chunks, with exact values, source-valid and AOI masks, and both quality masks, followed by version-validated completion. The gate requires all four requested output/source identities exactly once and complete nonoverlapping coverage of all 73,984 selected cells per layer; omitted or duplicate layers/chunks fail. A changed source ETag injected after five GETs during preparation fails with exit 1, and SIGINT at the same point exits -2; neither publishes a complete manifest. Two additional stream checks inject source mutation or consumer cancellation immediately after the first provisional chunk is received. Both exit 1 and emit no completion event, so a provisional value cannot be mistaken for a validated completed acquisition.

```sh
prototype-output/zarr-env/bin/python bench/wave2_dswx_s1.py \
  --replay --binary prototype-output/wave2/tile-ripper-native \
  --output prototype-output/wave2-dswx-s1/NEW-frozen.zarr
```

The replay additionally creates a sibling `.rasterio-reference` store and fault-case destinations under ignored `prototype-output`. The reference is a full output workflow; output encoding size differences are reported rather than normalized away.

## Geographic-selection boundary

`products::array_grid::resolve` returns `ResolvedSelection`: original explicit-CRS AOI, resolved source-global native index window, included-center count and membership policy. Prepared observations retain this alongside the actual grid, source metadata and version-bound physical plan. The CLI's JSON and human plans report these fields, scientific variables/quality policy, physical chunks, selected/decode estimates and memory admission. Describing a grid or resolving an index window does not authorize source execution.

Coordinate models stay separate from physical readers:

- Existing COG affine grids and SWOT's independently qualified WGS84 UTM source grids retain their existing adapters.
- NISAR uses original stored Float64 coordinate vectors, validated metadata/registration and the existing UTM polygon evaluator. The new accelerator rejects rows using inverse-latitude extrema on the qualified constant-northing rows, then binary-searches longitude on actual stored centers. It evaluates every candidate center in the original polygon. It never prunes using an approximately projected polygon or rounds a forward transform to indices.
- GOES uses original packed radian scan coordinates, sweep-x, the source ellipsoid, -75° origin and 35,786,023 m perspective height. No scan angle is relabeled as a distance. Invisible native centers remain separate from source missingness.
- SMAP global EPSG:6933 and north-polar EPSG:6931 have distinct formulas and dimensions. The [authoritative NSIDC N09 definition](https://github.com/nsidc/mapxmaps/blob/main/EASE2_N09km.gpd) places outer edges at (-9000000,9000000), with centers offset by half of 9000 m; no center is exactly at the pole. The source's Float32 geolocation and UInt16 row/column fields independently confirm that registration. A source field's fill does not erase a geometrically defined native center.

The NISAR geographic gate admits only the two inspected shapes, matching 10/20 m monotonic axes and canonical source UTM16N metadata. The accelerator's coordinate envelope is easting [300000,800000] m and northing [3000000,5000000] m. It reuses the existing UTM query limits: simple WGS84 polygons/closed holes, at most 5° per axis, latitude [-80,80], native zone vicinity and hemisphere. There are at most 65536 centers per axis, 256 input vertices/17 rings, and 256 million admitted center/vertex tests. The row-interval preparation holds at most 65536 small intervals within the product reservation; there is no billion-cell mask allocation.

NISAR and northern SMAP reuse the closed outer/hole boundary rule with the explicit 1e-10-degree numerical tolerance. Existing GOES/global-SMAP exact closed-center membership remains unchanged. Northern SMAP queries must stay in the northern hemisphere and use non-wrapping longitude rings; a seam-adjacent [179°,180°] query is valid. The mathematical LAEA domain and science coverage are distinct: some corners of the native square navigate south of the equator and still retain their raw source values and source-fill masks. Projection position never supplies a quality decision.

Curvilinear coordinates, irregular axes, unsupported registration/projection pairs, longitude-wrap geometries and other NISAR grids fail explicitly. Geographic zero-center requests fail before science acquisition. A successful selection with positive centers and zero usable measurements still produces valid raw/mask output: the NISAR corner case has 64 AOI centers and zero usable HHHH values. Footprint intersection is not a measurement-quality assertion.

## Independent evidence and execution

[NISAR comparisons](nisar-geographic-validation.json) cover geographic bounds, a triangular inclusion mask, a four-chunk crossing and a NaN corner. The [second NISAR comparison](nisar-additional-validation.json) separately checks the 20 m specimen. Every stored Float32 bit, source validity, native Float64 center and serialized stream agrees with HDF5-C/h5py, PROJ and GEOS. A [full-source oracle](nisar-full-source-coordinate-oracle.json) independently inverse-transformed all 1,229,401,152 original centers in bounded strips and recovered the same 64-center 8×8 window without candidate pruning.

[SMAP comparisons](smap-polar-validation.json) cover ordinary, near-pole, seam-adjacent and equatorial-edge AOIs for both AM and PM. They check raw values, quality words/policy, independently transformed coordinates, original source geolocation and original grid indices. Native-index corner cases separately preserve raw values and validity where the mathematical projection navigates south of the equator. The [full-grid PROJ oracle](smap-full-source-coordinate-oracle.json) independently recovers all four geographic windows from every native grid center. [GOES comparisons](goes-validation.json) check geographic, chunk-crossing and strided cases against h5py, independently opened NetCDF-C and PROJ. Zarr-Python and xarray reopen raw outputs with CF decoding disabled. Frozen PROJ/GEOS fixtures exercise boundary ties, holes, partial/empty overlaps, altered source extent, invalid axes, projection-domain limits and work admission.

[Bounded catalog/automatic discovery](catalog-workflows.json), [fault controls](faults.json), [Rust/human workflows](rust-workflows.json), [live-native validation](live-native-validation.json), [workflow measurements](performance.json) and the [final acceptance receipt](acceptance.json) record the remaining checks and limits. Bounded sparse mirrors refuse every uncaptured byte; original object sizes are not downloaded-file sizes. Extent hashes and strong ETags bind the references. Every writer still requires successful final source validation before atomic publication; failures/cancellation remove incomplete output. HDF5 storage initialization remains distinct from CF source fill, and AOI, source missingness, raw quality and derived policy masks stay independent.

The additional HVHV diagonal was evaluated as a distinct candidate: its inspected Float32 layout, initialization and radiometric convention match the real-valued model, but its HV calibration identity differs from HH. It is **not admitted** by the HHHH profile. A separate named HVHV profile would need its own selected-channel calibration provenance and bit/quality/output gate. This is a deliberate unimplemented candidate, not a claimed scientific incompatibility. Frequency B, other terms, complex covariance and RSLC/SLC remain unsupported.

## Normal workflow and reproduction

```sh
cargo build --locked --release --no-default-features --features native-cog,native-hdf5,authenticated-http --bin tile-ripper --example array_product --example array_faults
target/release/tile-ripper discover --product nisar-gcov-p1-fa-hhhh --bbox '-86.43,36.61,-86.41,36.63' --start 2026-10-22T10:55:00Z --end 2026-10-22T10:57:00Z --bands HHHH --limit 8
target/release/tile-ripper plan examples/product-nisar-geographic.json --human --auth earthdata --netrc PRIVATE_FILE
target/release/tile-ripper stream examples/product-nisar-geographic.json --values --auth earthdata --netrc PRIVATE_FILE
target/release/tile-ripper fetch examples/product-nisar-geographic.json --output NEW.zarr --auth earthdata --netrc PRIVATE_FILE
target/release/examples/array_product examples/product-nisar-geographic.json NEW-RUST.zarr --netrc PRIVATE_FILE
```

The same request may omit `observations` to perform bounded discovery during preparation; polygon queries submit their conservative geographic bounding box to CMR, with exact native-center membership deferred to preparation. It must resolve exactly one observation for array acquisition. Named-product requests accept geographic AOIs directly. No manually resolved pixel window is required. Equivalent northern SMAP and mesoscale GOES requests are versioned beside this report. Native-index selection remains available.

The reference environment is `reference.txt`. Run `bench/wave4_inspect.py FAMILY` only to inspect/capture bounded real sources; protected inspections use an explicit private local netrc internally. Then run `bench/wave4_geographic.py fixture|nisar|additional|smap|goes|full_oracle|polar_oracle|benchmark`, and `bench/wave4_acceptance.py faults|workflow|catalog|live`. `--capture` extends only missing extents under an 8 MiB source cap and seals after source revalidation; repeated comparisons use frozen mirrors. Live access is a separate check. Performance measurements compare fresh native and independently implemented mature-reader processes; source selection/index work differs, and no general speed advantage is claimed.
